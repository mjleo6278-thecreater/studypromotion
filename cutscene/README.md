# 업데이트 컷씬

업데이트마다 "이 기능을 왜 만들었나"를 짧은 3D 컷씬으로 보여 준다. 앱에서는 '업데이트 이야기'라고 부른다.

- `character.html` : 개발자 폰 캐릭터 돌려 보기·표정 보기 (배포본에 안 들어감)
- `index.html` : 컷씬 #1 "샤워하다 생긴 기능" (v4.5 말로 복습 이야기)

## 앱에 넣은 방법 (v4.5, 버전 번호는 그대로 둔 조용한 배포)
- `tools/build.js`가 `index.html`과 그 페이지의 스크립트만 `dist/web/cutscene/`에 복사한다. `sw.js` ASSETS에도 같은 목록이 있어야 한다(빌드가 확인). 오프라인에서도 열린다.
- `sw.js`: `/cutscene/` 페이지는 앱 index.html로 바꿔치지 않는다 (iframe도 navigate 요청이라서).
- `js/story.js`: 화면 전체 iframe으로 `cutscene/index.html?embed`를 연다.
  - 저절로: 그 버전(4.5, 4.5.x)을 쓰는 사람이 아직 안 봤으면 한 번. 지난번에 연 버전(`studypromotion.appVersion`)이 없으면 새로 설치로 보고 띄우지 않는다. 그래서 `js/backup.js`보다 먼저 읽힌다.
  - 띄우지 않을 때: 시작 화면·타이머·스톱워치·잠금·확인 창·시트·말로 복습·게임·글자 입력 중. 1분쯤 기다려도 바쁘면 다음에 열 때.
  - 본 이야기: `studypromotion.storySeen` (id를 쉼표로).
  - 업데이트 소식 4.5 칸의 `data-story="shower-1"` 단추로 다시 본다. 웹 배포본에서만 보인다(한 파일 버전·미리 보기에는 컷씬 파일이 없음).
  - 뒤로 가기·Esc·'닫기'로 닫힌다. 열려 있는 동안 뒤의 앱은 inert, 폰 상단 바는 무대 색.
- `?embed`(player.js): 시작 전·끝 화면의 위쪽 단추가 '닫기', 끝 화면에 '말로 복습 해 보기'(primary)와 '다시 보기'. `&try=0`이면 말로 복습 단추를 뺀다(말로 복습을 끈 사람).
  - 부모 창에 `postMessage({ sp: 'cutscene', action: 'close' | 'try' | 'nogl' }, 같은 주소)`.
  - '말로 복습 해 보기' → 오늘 복습할 카드가 가장 많은 덱을 열고 말로 복습 시작 창.
- 시험: `node tests/story.e2e.js` (빌드한 dist/web을 띄워 위 내용을 모두 눌러 본다).
- 새 이야기를 만들 때: `js/story.js` STORIES에 하나 더, 그 버전 소식에 단추, `sw.js` ASSETS, 빌드 목록.

## 설계 (만들기 전에 정한 것)

**목표**: 개발자를 투영한 복셀(픽셀 느낌 3D) 체스 폰 캐릭터와, 그 캐릭터가 겪은 불편에서 기능이 나오는 30초 안팎의 컷씬.

**우선순위** (부딪히면 위가 이김)
1. 자막을 안 읽어도 그림만으로 이야기가 읽힌다 (샤워 중 → 손에 거품 → 화면이 안 눌림 → 말로 하자 → 말하니 넘어감).
2. 캐릭터가 귀엽고 표정이 읽힌다 (기본·깜빡·답답 ><·번뜩·신남).
3. 폰에서 부드럽게 돈다.
4. 효과(물줄기·김·거품·반짝임·소리)는 그다음.

**제약**
- 아무것도 내려받지 않는다: 3D는 WebGL을 직접 쓰고(라이브러리 없음), 자막은 앱에 이미 있는 Pretendard를 작은 크기로 그린 뒤 픽셀로 키운다, 소리는 Web Audio로 합성한다.
- 참고 사진(복셀 게임들)은 분위기·화풍만 참고한다. 그 캐릭터·게임을 따라 그리지 않는다.
- 앱 main 합치기·배포는 사용자 동의 전에는 하지 않는다.

**숫자 목표**
- 화면: 폰 세로 360×640, 390×844, 가로 844×390, 태블릿 768×1024에서 캐릭터·폰 화면·자막이 잘리지 않는다.
- 자막: 한 줄 13자 이하, 두 줄 이하. 글자 높이 화면에서 20px 이상(360 폭). 한 자막은 최소 2.4초 보인다.
- 길이: 28~34초, 장면 6개.
- 그리기: 삼각형 6만 개 이하, 한 프레임 그리기 호출 120번 이하.
- 단추(건너뛰기·소리·다시 보기): 44×44px 이상. 건너뛰기는 언제 눌러도 끝 화면으로 간다.
- 파일: 컷씬 코드 전체 150KB 이하, 외부 요청 0개(글꼴 제외).

**검증**
- 시간을 넣으면 그 순간을 그리는 시험용 고리 `Cutscene.renderAt(t)` → 같은 시각은 늘 같은 그림.
- Playwright로 폰 폭마다 장면별 스크린샷, 시작·건너뛰기·다시 보기·소리 단추를 눌러 본다.
- 소리는 같은 일정으로 오프라인 렌더링해서 소리 파일이 비어 있지 않은지 확인하고 영상에 붙인다.
- 화면 비평가 서브에이전트: 코드와 내 설명 없이 스크린샷과 참고 사진만 보고 ① 무슨 이야기로 읽히는지 ② 고칠 점 5개까지. 라운드마다 새 비평가.

**끝 조건**: 비평가가 낸 중요한 고칠 점이 남지 않거나 3라운드를 마침 + 위 화면 크기 스크린샷 + 영상(MP4)·GIF.

## 결과 (2026-11-23)

**숫자 목표 확인** (Playwright, 헤드리스 크롬 SwiftShader)
- 삼각형 최대 약 4.1만 개 (목표 6만 이하), 그리기 호출 최대 42번 (목표 120 이하).
- 코드 약 110KB (목표 150KB 이하), 외부 요청 0개. 미리 보기 한 파일(글꼴 조각 19개 포함)은 약 780KB.
- 한 프레임 그리기 중간값 약 3ms(소프트웨어 그래픽에서). 처음 열기 약 0.4~0.5초(로컬).
- 소리: 오프라인 렌더링 최고 크기 0.48 (비어 있지 않음, 넘치지 않음).
- `tests/cutscene.e2e.js`: 390×844, 360×640, 844×390, 768×1024에서 시작·소리 끄기/켜기·건너뛰기·다시 보기·끝에서 멈춤, 단추 44px 이상, 캐릭터 화면 표정 단추 → 모두 통과.

**화면 비평가 3라운드** (라운드마다 새 비평가, 스크린샷 14장 + 참고 사진만 봄)

| 라운드 | 토큰 | 걸린 시간 | 점수 | 주로 고친 것 |
|---|---|---|---|---|
| 1 | 약 6.8만 | 약 2분 | 6/10 | 해결 장면(입·말풍선·소리 물결·체크·카드 넘김), 거품 손 보여 주기, 끝 화면 손이 폰을 가림, 색 대비(테라코타 벽·따뜻한 빛), 가로 화면 겹침 |
| 2 | 약 6.7만 | 약 2분 | 6/10 | 손·거품·머리·물이 다 흰색 → 청록 장갑 손, 큰 체크가 카드를 가림 → 작은 배지, 머리 덩어리 정리, 효과 글자 크게, 자막 아이콘 겹침 |
| 3 | 약 8.9만 | 약 3분 | 6/10 | 해결책 '말로'가 그림에 없음 → '!' 뒤 마이크 생각 풍선·폰 위 마이크 표시·소리 물결이 폰 마이크 칸까지, 정답 글자를 거품 자국·반짝이가 가림, 실패 순간 얼굴이 안 보임 → 물러나며 놀란 얼굴, 만세 손이 위 단추 줄을 가림 |

- 비평가마다 내가 놓친 것을 3~4개씩 새로 찾았다. 점수는 그대로였지만, 고친 것은 다음 비평가가 다시 지적하지 않았다.
- 비평가끼리 다른 의견도 있었다(1: 체크를 크게 ↔ 2: 체크가 카드를 가리니 작게). 2를 따르고 3에서 폰 밖 모서리로 옮겼다.
- 고치지 않은 것: 3라운드 4번 '끝 화면에 바로 써 보기·닫기 단추'는 앱에 넣을 때 할 일(아래). 5번 '배경 흐림'은 흐림 효과가 없어서 그림자 해상도만 올렸다.

**앱에 넣을 때 할 일 (아직 안 함)**
- 업데이트 소식 창에서 처음 한 번 보여 주기, 끝 화면에 '바로 써 보기'(주 단추)·'닫기'.
- 말로 외우는 단어장 기능 자체(음성 인식·채점)는 따로 만들어야 한다.

## 2차 (2026-11-24, 사용자 피드백: "캐릭터를 조금 더 하찮게, 화질과 프레임 우선")

**화질·프레임**
- 3D를 화면 밀도 3까지 그린다(예전 2까지). 재생 중 45프레임 평균이 24ms(약 42fps)보다 느리면 해상도를 0.8배씩 1.5까지 자동으로 낮춰 프레임을 지킨다.
- 픽셀 글자·단추는 한 칸이 기기 픽셀로 정수가 되게 맞춘다(2.75배 안드로이드 폰에서도 칸 크기가 고름).
- 폰에서 재생할 때는 그림을 남겨 두지 않는다(preserveDrawingBuffer는 시험·영상 뽑기에서만). 투명 단추는 바뀐 것만 고친다.
- 영상: 1170×2532, 60fps, 무손실 PNG 프레임을 ffmpeg에 바로 넣어 H.264(crf 17, slow)로. 예전 780×1688·30fps·JPEG 프레임.

**캐릭터 (더 하찮게)**
- 넓적한 떡 머리에 콩알만 한 눈 두 개를 멀찍이, ㅅ 입, 삐친 머리카락 한 가닥, 쪼끄만 손(0.72배), 가는 목.
- 표정: 기본(콩알 눈·ㅅ), 신남(^ ^), 답답(> <, 물결 입), 멍(세로 콩알), 번뜩(이때만 눈이 커짐).

## 3차 (2026-11-24, 사용자 정정: "외모가 아니라 픽셀이 너무 많다, 길건너 친구들 캐릭터 정도의 픽셀로")
- 캐릭터를 큰 블록으로 다시 지었다: 가로 6칸 × 세로 10칸, 한 칸 = 2.2 단위. 받침 6×6 · 4×4 · 목 2×2 · 청록 목도리 6×6 · 네모 머리 6×5×6, 손은 한 칸짜리 청록 블록. (2차의 콩알 눈·삐친 머리 같은 '외모 하찮게'는 되돌림)
- 얼굴은 반 칸 격자: 눈은 한 칸 네모, 표정은 기본·신남·답답(\ /)·멍·번뜩(흰 점)·말하기.
- 장면이 쓰는 좌표(손 위치·머리 높이 16.5)는 그대로라 컷씬 연출은 바꾸지 않았다. 삼각형 약 3.9만 개.

## 4차 (2026-11-24 밤, 사용자: "얼굴 그림자가 부자연스러우니 빼 줘, 폰의 일부분이 자꾸 벽에 껴 있다")
- 원인: 캐릭터를 큰 블록(머리 13.2, 돌면 대각선 18.7)으로 바꾸면서 자리는 그대로 둬서, 0.05초마다 잰 641장면 중 636장면에서 머리·몸이 벽·바디워시 통·선반·수도꼭지에 파고들었다. 휴대폰도 위쪽이 벽에 0.9 박혀 있었다.
- 자리를 다시 잡았다: 바디워시는 왼쪽 선반(-23~-14), 폰은 오른쪽 선반(14~27), 선반 윗면 8(목도리 아래), 수도꼭지 27~29(머리 위), 폰은 선반에 서서 위가 벽에 기댐. 바디워시 장면은 왼쪽으로 깡충 → 왼손으로 펌프(통 위로 넘어가게), 카메라도 왼쪽. 욕실 왼쪽을 넓혀(left 40) 카메라가 방 안에 있게, 고무 오리는 뺐다.
- 물줄기가 머리 네모 안으로 떨어지면 머리 위에서 끊는다(옆에 서 있어도 뚫고 지나가지 않게).
- 얼굴: 머리는 그림자를 받지 않고(`recv: false`, engine.js가 물체마다 그림자 받기를 끔), 눈·입·볼은 그림자를 만들지 않으며 두께도 얇게(0.05칸).
- 시험: `tests/cutscene.e2e.js`가 0.05초마다 캐릭터·폰이 벽·선반·통·수도꼭지·폰에 들어가는지 재서 0이어야 통과.
